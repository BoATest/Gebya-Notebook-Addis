What a partial sale does to the Today report after the fix: reportSelectors.js now tracks exactly how much was received, by which method, and how much is still owed — no more double-counting.

The scenario we walk through

What the sale row actually stores
The report reads these fields to decide cash vs bank vs owed
FieldValueRole
type'sale' identifies a sale row
sale_settlement_mode'partial' NEW marks this as a partial sale
amount1000 full sale value → totalSold
paid_amount300 KEY what actually changed hands
cash_received0 0 because it was paid via bank, not cash
payment_type'partial' kept so the row is still classed as a partial
payment_provider'CBE' the bank used → classified as transfer
remaining_amount700 KEY still owed → new Dubie
credit_amount700 same 700, stored on the sale row too
new field the report keys on now read where it wasn't before

// reportSelectors.js — the rule that fixes it
collectedAmount(row) = paid_amount // if partial
                  = amountOf(row) // otherwise
transferRecorded = Σ collectedAmount(transfer rows)
